* Research question

What behavioral capabilities must =llm-agent-cl= expose to reach credible LangChain + LangGraph feature parity while remaining a reusable Common Lisp library rather than a hosted agent harness?

The maintainer has explicitly resolved the earlier ambiguity: LangChain + LangGraph parity is required, and embeddings/vector stores/document loaders must be included in the first major parity milestone rather than left for an indefinite later package family.

* Verified baseline

Current LangChain provides standard provider-neutral model interfaces, messages/content blocks, standalone and agent model invocation, streaming, tool calling, structured output, multimodality, reasoning metadata, model profiles/capability data, middleware, runtime context, short-term/long-term memory integration, retrieval components, and a broad integration ecosystem.

Current LangGraph is the lower-level stateful orchestration layer. Current documented capabilities include explicit graph state and reducers, nodes/edges, conditional routing, dynamic =Send= fan-out, =Command= state-update plus routing/resume semantics, parallel supersteps, persistence/checkpoints, pending writes for fault tolerance, interrupts/resume, subgraphs, short-term memory, long-term stores, streaming, typed event projections, replay/fork time travel, and both graph and functional APIs.

LangChain's current component architecture also treats embedding models, retrievers, document processing, and vector stores as first-class component categories. Its retrieval pipeline explicitly composes document loaders -> text splitters -> embedding models -> vector stores -> retrievers -> generation. Therefore omitting these from the first major parity milestone would not satisfy the maintainer's parity requirement.

* Design implications

1. The public library must be layered around canonical values and protocols, with provider/transport details at the boundary.
2. The high-level agent must be implemented on the graph/state execution layer so checkpointing, interrupts and streaming are not retrofits.
3. Sync/async are one semantic contract with separate execution/transport adapters.
4. Event streaming must represent provider deltas and orchestration events through a common typed stream.
5. Persistence is optional to construct but checkpoint/store protocols are core.
6. Retrieval is a first-major-milestone package family, not an optional someday integration.
7. The standard interfaces are the parity boundary. Third-party integration count is explicitly not the parity metric.

* First-major-milestone acceptance boundary

The milestone cannot be called LangChain + LangGraph parity-complete until automated conformance tests exercise at least:

- chat sync/async/batch/stream;
- tools + structured output + middleware;
- multi-turn/checkpoint/interrupt/resume;
- graph reducers/conditional routing/Send/Command/parallel branches/subgraphs;
- checkpoint replay/fork and pending-write recovery;
- documents/loaders/splitters;
- embeddings + caching;
- vector store + retriever + a complete minimal RAG workflow;
- MCP client and server adapter basics;
- typed event streaming across model/tool/graph/retrieval operations.

* Non-goals

- No hosted agent server.
- No StarIntel-specific actor, database, or schema dependency.
- No exact Python API clone.
- No requirement to reproduce every LangChain third-party integration package before a 1.0 release.

* Footnotes and Glossary

- *HITL*: human in the loop.
- *Checkpoint*: persisted snapshot sufficient to resume or inspect an execution thread.
- *Pending write*: a successful task's durable state contribution saved before its parallel superstep fully commits.
- *Semantic parity*: comparable behavior and extension points without copying another language's API shape.
