* Research question

What behavioral capabilities must =llm-agent-cl= expose to be credibly comparable to current LangChain + LangGraph while remaining a reusable Common Lisp library rather than a hosted agent harness?

The user wording “langchain and language” is interpreted as *LangChain and LangGraph* because the requested feature set includes both a LangChain-like model/agent layer and LangGraph-like stateful orchestration. This interpretation remains reviewable.

* Verified baseline

Current LangChain presents a standard model interface across providers and a configurable agent abstraction built from models, tools, prompts, and middleware. Its model layer supports normal invocation, streaming, tool calling, structured output, multimodal content, usage metadata, and conversation messages. LangChain agents maintain message state, execute tool loops, expose middleware, and inherit LangGraph capabilities.

Current LangGraph is the lower-level orchestration layer for long-running, stateful agents. Its documented capability classes include durable execution, persistence/checkpoints, human-in-the-loop interrupts, memory, streaming, deterministic + agentic graph composition, and subgraphs.

* Design implications discovered by research

1. The public core should be layered: canonical values/errors -> model/provider contracts -> tools/structured output -> agent loop -> graph/checkpoint layer -> MCP adapters.
2. The high-level agent API must be implementable on top of the lower-level state/graph primitives, matching the LangChain-over-LangGraph relationship without copying Python object models.
3. Sync and async are not separate feature sets. They require one semantic contract and different transport/execution bindings.
4. Streaming must cover both provider token deltas and orchestration events.
5. Persistence is optional at construction time but its interfaces are core; durable behavior cannot be retrofitted cleanly if state transitions are not explicit from the start.

* Non-goals

- No hosted agent server.
- No StarIntel-specific actor, database, or schema dependency.
- No exact Python API clone.
- No claim that a finite initial provider list equals the entire LangChain integration ecosystem.

* Unresolved questions

- Whether embeddings/vector stores/document loaders belong in the first major parity milestone or a later package family.
- Exact public Common Lisp idioms for async values and graph state should be chosen only after dependency and portability research.
- Whether the production async transport is hardened Carrier or a small libcurl-multi client; see research 003 and 007.

* Footnotes and Glossary

- *HITL*: human in the loop.
- *Checkpoint*: persisted snapshot sufficient to resume or inspect an execution thread.
- *Semantic parity*: comparable behavior and extension points without copying another language's API shape.
