* Dexador

Dexador is the required synchronous Common Lisp HTTP transport. It should remain behind the common transport protocol rather than leak into provider APIs. Provider code expresses method, URL, headers, body, response mode, deadline/cancellation metadata and stream sink/source through library-level contracts.

* Carrier: canonical maintained asynchronous client

The async direction is now resolved. =https://github.com/lost-rob0t/carrier= is the canonical maintained fork for llm-agent-cl. GitHub identifies it as a fork of =orthecreedence/carrier=. At the time of this research its =master= tree is still the upstream =95ea9edba80f67598bfde550a170a2f787970223= tree, so no production hardening has yet been applied.

Carrier is MIT-licensed and built on =cl-async=, =cl-async-ssl=, Blackbird, =fast-http=, Quri and support libraries. Its request contract already supplies the key shape required by OpenRouter SSE: non-blocking execution, response-header callback, incremental response-body byte callbacks and promise completion.

The llm-agent-cl adapter must not expose Blackbird or Carrier socket types publicly. Carrier is a transport backend, not the async semantic model of the entire library.

* Why the fork must be hardened before use

**TLS verification is a hard blocker.** Current =cl-async-ssl:tcp-ssl-connect-new= loads verify paths but explicitly configures =SSL_VERIFY_NONE=. SNI is set, but SNI does not authenticate the peer. API keys and model traffic must never flow over this path until certificate-chain and hostname verification fail closed.

**Cancellation is not first-class.** Stock Carrier returns a promise while keeping the socket lexical inside =request=. The maintained fork needs a public request handle with idempotent cancellation.

**Connection reuse is absent.** Stock Carrier closes the socket at response completion. The maintained fork needs bounded origin-keyed keep-alive reuse and reusable TLS contexts.

**Timeout semantics are incomplete.** Read timeout exists, but production behavior needs connect, read/idle and absolute deadlines with one terminal-state machine.

**Request serialization needs hardening.** The current request builder passes bodies through string serialization, which is not an acceptable generic binary-body contract. The fork should build header/body octets and support bounded streaming uploads.

**Redirect security must be explicit.** Authorization/cookie headers must not cross origins accidentally; redirect method rewriting and loop limits require deterministic tests.

* Maintained-fork direction

The active implementation direction is no longer “Carrier or libcurl.” The maintainer has selected and will maintain =lost-rob0t/carrier=. The project should therefore:

1. harden that fork as a standalone async HTTP client;
2. preserve reasonable backward compatibility for existing Carrier callers;
3. add new production client/request-handle APIs without forcing llm-agent-cl semantics into Carrier;
4. tag/release a tested hardening version before llm-agent-cl pins it;
5. keep llm-agent-cl's transport conformance suite backend-neutral.

The earlier libcurl-multi research remains useful contingency evidence but is =SUPERSEDED= as the active path. Switching transports later requires a new maintainer decision; it is not an automatic fallback during implementation.

* Unified sync/async semantics

Dexador and Carrier adapters must expose equivalent library-level outcomes:

- request accepted / response received;
- response headers before body completion where streaming requires it;
- body byte stream or complete body;
- explicit cancellation;
- absolute deadline plus connect/read/idle timeout policy;
- typed DNS/TLS/connect/protocol/status/decode/cancelled errors;
- deterministic cleanup exactly once;
- optional proxy/TLS policy;
- connection reuse where supported;
- observability metadata and byte counts.

Async invocation must be natively asynchronous. “Run Dexador in a background thread” is not the primary async provider transport.

* SSE layer

SSE parsing belongs above HTTP so sync and async transports feed identical bytes into one parser. Required parser tests include:

- UTF-8 code points split across reads;
- CRLF/LF framing;
- comment/keepalive lines;
- multiple =data:= lines;
- events split at every possible byte boundary;
- terminal =[DONE]= or provider equivalent;
- malformed JSON;
- tool-call JSON fragmented across events;
- provider error after successful deltas;
- cancellation and slow-consumer backpressure.

The output is typed stream events including text/content deltas, reasoning/metadata deltas, tool-call deltas, usage, completion and terminal errors.

* Retry and cancellation rules

Retries are bounded, policy-driven and jittered where delay applies. Never automatically replay a request after observable content/tool-call side effects. Cancellation propagates graph -> agent -> provider -> HTTP request handle and yields one typed cancelled terminal state.

* Footnotes and Glossary

- *Backpressure*: preventing a producer from unboundedly outrunning a stream consumer.
- *Transport adapter*: implementation mapping llm-agent-cl's HTTP contract to a concrete HTTP library.
- *SNI*: TLS Server Name Indication; routing metadata, not peer verification.
