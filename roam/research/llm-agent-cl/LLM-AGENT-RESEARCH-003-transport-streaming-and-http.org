* Dexador

Dexador is a Common Lisp HTTP client with connection pooling and condition-based HTTP failure behavior. It is MIT licensed and is the required synchronous transport for this project.

Dexador should be hidden behind a transport protocol rather than exposed from provider APIs. Provider code should express request method, URL, headers, body, response mode, deadline/cancellation metadata, and stream sink/event source through library-level contracts.

* Carrier: verified asynchronous Common Lisp client

Carrier is the actual asynchronous Common Lisp HTTP client that resolves the earlier search gap. Its upstream is =orthecreedence/carrier=. The ASDF system identifies version =0.1.1= under the MIT license and depends on =cl-async=, =cl-async-ssl=, Blackbird, =fast-http=, Quri, and related support libraries.

Carrier's =request= function returns a Blackbird promise. Its public contract includes response-header callbacks, response-body callbacks receiving byte-array slices, a finish callback, redirects, cookies, and read timeout configuration. This is sufficient in shape to drive OpenRouter HTTP/1.1 Server-Sent Events without buffering the complete response.

The upstream implementation constructs requests itself, opens a non-blocking =cl-async= TCP or TLS connection, feeds response bytes through =fast-http=, and calls the body callback incrementally. The SSE parser should remain above Carrier so provider and transport code do not couple to HTTP chunk boundaries.

* Why stock Carrier is not production-ready unchanged

Carrier satisfies the requirement to *find a native async Common Lisp HTTP client*, but current upstream cannot be the production backend without remediation.

**TLS verification is a hard blocker.** Carrier uses =cl-async-ssl= for HTTPS. The current =cl-async-ssl:tcp-ssl-connect-new= creates an SSL context, loads default verify paths, then explicitly configures =SSL_VERIFY_NONE= and contains a TODO for better verification support. SNI is set, but SNI is not certificate/hostname verification. Provider credentials and model traffic must never be sent through a transport that does not verify the remote certificate and hostname.

**Cancellation is not first-class.** Carrier keeps the socket in lexical state inside =request= and returns only a promise. The implementation closes the socket on redirect and completion, but callers have no supported request handle that can be cancelled to deterministically tear down an in-flight request. llm-agent-cl requires cancellation propagation from graph/agent execution to provider and socket.

**Connection reuse is absent.** Carrier closes the socket after a completed response. It therefore does not provide a connection pool or persistent keep-alive reuse. This matters for provider latency, TLS handshake overhead, and concurrent production workloads.

**TLS context reuse is an upstream performance gap.** Carrier issue #25 reports that creating and initializing the SSL context per request dominated high-rate request workloads; the reporter observed a large throughput improvement by reusing an SSL context. The feature is not part of Carrier's public API.

**SSL compatibility remains an upstream issue.** Carrier issue #16 documents HTTPS sites that fail under its SSL path.

**Request-body streaming is absent.** Carrier issue #17 requests streaming request bodies. OpenRouter's initial JSON request bodies are bounded and do not require this feature, but the generic transport contract should not pretend it exists.

**Testing is thin.** Carrier issue #13 explicitly asks for HTTPBin testing; a production dependency therefore requires llm-agent-cl-owned conformance and live integration tests regardless of upstream test coverage.

* Production backend strategy

The async HTTP interface must not expose Carrier-specific promise/socket types. The future design should use this order:

1. **Hardened Carrier path** — fork or patch Carrier/cl-async-ssl only if verified certificate + hostname validation, cancellation, deterministic cleanup, connection reuse/TLS-context reuse, and required timeout semantics can be implemented cleanly and covered by tests.
2. **libcurl multi path** — if Carrier hardening is brittle, implement a small Common Lisp async client/adapter over libcurl's multi interface using CFFI. libcurl multi is event-driven, supports many concurrent transfers in one thread, permits removing an easy handle to cancel a transfer, and can integrate with an event loop. Modern libcurl also provides mature TLS verification, connection reuse, HTTP/2 multiplexing, and HTTP/3 where built with support.

A libcurl-multi adapter is preferable to 'Dexador in a worker thread' because it is genuinely asynchronous and preserves cancellation/backpressure semantics at the network layer.

* Unified sync/async semantics

Both transports must expose equivalent outcomes:

- request accepted / response received;
- response headers available before body completion where streaming requires it;
- body byte stream or complete body;
- cancellation;
- absolute deadline and connect/read timeout policy;
- typed DNS/TLS/connect/protocol/status/body-decode errors;
- deterministic cleanup;
- optional proxy/TLS configuration;
- connection reuse;
- observability metadata.

Async invocation must not be 'run Dexador in a background thread' except as a separately documented portability fallback. Native async transport behavior is the requirement.

* SSE layer

SSE parsing belongs above HTTP so both transports feed identical bytes/events into one parser. Required parser tests include:

- UTF-8 code points split across reads;
- CRLF and LF framing;
- comment/keepalive lines;
- multiple =data:= lines;
- events split at every possible byte boundary;
- terminal =[DONE]= or provider equivalent handling;
- malformed JSON;
- a provider error after earlier successful deltas;
- consumer cancellation and slow-consumer backpressure.

The output should be typed stream events, including content deltas, reasoning/metadata deltas, tool-call deltas, usage, completion, and terminal errors.

* Retry and cancellation rules

Retries must be bounded, policy-driven, jittered where delay applies, and classified by failure stage. Never automatically replay a request after tokens/tool calls have been observed. Cancellation must propagate from agent/graph -> provider -> HTTP transport and produce a typed cancelled terminal state.

* Footnotes and Glossary

- *Backpressure*: preventing a producer from unboundedly outrunning a stream consumer.
- *Transport adapter*: implementation that maps the library's HTTP contract to a concrete HTTP library.
- *SNI*: TLS Server Name Indication; it selects a server identity but does not itself verify the certificate.
- *libcurl multi*: libcurl's non-blocking interface for driving many transfers from one event loop/thread.
