* Goal and invariants

Implement OpenRouter as the first production provider adapter without allowing OpenRouter JSON, HTTP/SSE chunking, Dexador objects, Carrier handles or Blackbird promises to become public llm-agent-cl semantics.

Invariants:

1. Canonical messages/results/events from Design 001 are the provider boundary.
2. Request serialization is deterministic for the same canonical request/options.
3. SSE is decoded as a byte stream; HTTP chunk boundaries have no semantic meaning.
4. Tool arguments are not parsed until assembly is complete.
5. Exactly one terminal state wins completion/failure/cancellation/deadline races.
6. No transparent retry occurs after semantic stream output has been exposed.
7. Unsupported required capabilities fail explicitly; fields are never silently dropped.
8. Provider-native metadata is preserved in namespaced extensions.

* Systems and package boundaries

Proposed systems:

- =llm-agent/sse= — transport-independent incremental SSE decoder;
- =llm-agent/transport-dexador= — synchronous transport backend;
- =llm-agent/transport-carrier= — asynchronous backend pinned to the maintained Carrier fork release;
- =llm-agent/provider-openrouter= — OpenRouter chat/models/embeddings/capability mapping.

* Provider client

An OpenRouter client/config contains:

- API key or deferred credential resolver;
- base URL, default =https://openrouter.ai/api/v1=;
- default chat model;
- default embedding model;
- routing/provider preferences;
- optional attribution headers/site metadata;
- model capability cache policy;
- transport selection/config;
- retry policy;
- middleware/event hooks.

Representative implementation shape:

#+begin_src lisp
(defclass openrouter-client (llm.provider:model-client)
  ((config :initarg :config :reader openrouter-config)
   (transport :initarg :transport :reader openrouter-transport)
   (capability-cache :initarg :capability-cache
                     :reader openrouter-capability-cache)
   (retry-policy :initarg :retry-policy :reader openrouter-retry-policy)))

(defun make-openrouter-client (&key config transport retry-policy)
  ...)
#+end_src

Configuration resolution follows Design 001: explicit call > client > dynamic > process default > =OPENROUTER_API_KEY= for credentials.

The resolved API key is revealed only while constructing the HTTP Authorization header and must not be copied into provider metadata, stream events or checkpointable values.

* Endpoint families

**Chat Completions** is the initial stable chat foundation at =POST /chat/completions=.

**Models** provides discovery/profile data used for capability checks and routing. Preserve the full OpenRouter model record and normalize context length, modalities, supported parameters, pricing metadata and fetched timestamp.

**Embeddings** uses =POST /embeddings= and the embeddings model listing endpoint. Support single and batch inputs, dimensions/encoding/input-type options where accepted, provider routing and usage normalization.

**Responses** remains an optional beta endpoint family. It may have an adapter later but cannot define core conversation state or replace Chat Completions in the first production slice.

* Canonical request object at provider boundary

Provider invocation receives canonical messages plus a provider-neutral option object/map. A representative normalized request before OpenRouter mapping is:

#+begin_src lisp
(make-model-request
 :model "openai/gpt-5"
 :messages (list (make-user-message "weather in Columbus?"))
 :tools (list weather-tool)
 :tool-choice :auto
 :temperature 0.2
 :structured-output nil
 :extensions '((:openrouter . ((:provider . ((:sort . "throughput")))))))
#+end_src

The provider adapter validates canonical content/tool/schema semantics before serialization.

* Chat request mapping

Translate canonical messages/content/tools to OpenRouter JSON. Reject unsupported canonical content blocks explicitly unless a documented provider fallback exists.

Representative mapping:

#+begin_src lisp
(defgeneric encode-openrouter-message (message))
(defgeneric encode-openrouter-content-block (block))

(defun encode-openrouter-chat-request (request)
  (jzon-object
   "model" (model-request-model request)
   "messages" (map 'vector #'encode-openrouter-message
                   (model-request-messages request))
   "tools" (and (model-request-tools request)
                (map 'vector #'encode-openrouter-tool
                     (model-request-tools request)))
   "stream" (model-request-stream-p request)))
#+end_src

Illustrative JSON for one tool:

#+begin_src json
{
  "model": "openai/gpt-5",
  "messages": [
    {"role": "user", "content": "weather in Columbus?"}
  ],
  "tools": [
    {
      "type": "function",
      "function": {
        "name": "weather",
        "description": "Get weather",
        "parameters": {
          "type": "object",
          "properties": {"city": {"type": "string"}},
          "required": ["city"]
        }
      }
    }
  ]
}
#+end_src

Provider-specific request extensions for routing, transforms and future fields live under the OpenRouter extension namespace. They never become mandatory fields of other provider adapters.

Tool definitions include canonical name, description and JSON Schema parameters. Tool-call ids are never regenerated after provider response normalization.

* Structured output

Canonical structured-output request supports:

- schema/name;
- strict flag defaulting true when provider-native enforcement is selected;
- provider-native strategy preference;
- tool-mediated fallback preference;
- final validation policy.

Representative canonical shape:

#+begin_src lisp
(defclass structured-output-spec ()
  ((name :initarg :name :reader structured-output-name)
   (schema :initarg :schema :reader structured-output-schema)
   (strict-p :initarg :strict-p :initform t :reader structured-output-strict-p)
   (strategy :initarg :strategy :initform :provider-native
             :reader structured-output-strategy)
   (fallback :initarg :fallback :initform :error
             :reader structured-output-fallback)))
#+end_src

For OpenRouter provider-native strategy emit:

#+begin_src json
{
  "response_format": {
    "type": "json_schema",
    "json_schema": {
      "name": "result",
      "strict": true,
      "schema": {"type": "object"}
    }
  }
}
#+end_src

Before dispatch, use model capability data when available. When routing through multiple providers and the request requires structured output/tools/etc., apply OpenRouter's =require_parameters= routing option where appropriate.

Stale/absent capability information cannot cause silent field removal. Caller policy chooses among:

- =:require-known= -> fail before dispatch if support cannot be established;
- =:attempt= -> send required field and let provider answer;
- explicit fallback strategy -> caller-selected alternative only.

For streaming structured output, emit raw/partial structured-text deltas as stream events. Parse/validate the complete JSON only at terminal completion. A syntactically incomplete partial value is not a schema error until the stream ends unexpectedly or completion is declared.

* SSE decoder

The SSE system accepts arbitrary octet chunks and incrementally decodes UTF-8/framing. It must handle:

- UTF-8 split inside a multibyte code point;
- CRLF or LF lines;
- blank event delimiters;
- =:= comments/keepalives;
- repeated/multiline =data:= fields;
- optional event/id/retry fields;
- EOF with an incomplete event;
- bounded internal buffers/body/event size.

OpenRouter mapping then interprets =data:= payloads as JSON or terminal =[DONE]=. HTTP chunk boundaries are irrelevant.

** Decoder state

#+begin_src lisp
(defclass sse-decoder ()
  ((utf8-state :initarg :utf8-state :reader sse-utf8-state)
   (line-buffer :initform (make-octet-buffer) :accessor sse-line-buffer)
   (data-lines :initform '() :accessor sse-data-lines)
   (event-name :initform nil :accessor sse-event-name)
   (event-id :initform nil :accessor sse-event-id)
   (retry :initform nil :accessor sse-retry)
   (bytes-seen :initform 0 :accessor sse-bytes-seen)
   (limits :initarg :limits :reader sse-limits)))

(defgeneric feed-sse-octets (decoder octets start end emit))
(defgeneric finish-sse-decoder (decoder emit))
#+end_src

The decoder does not parse JSON. It emits complete SSE events to the OpenRouter layer.

** Parsing state machine

#+begin_src text
OCTETS
  |
  v
incremental UTF-8 decode
  |
  v
line accumulator -- newline --> parse field
  |                            |
  |                            +-- ':' comment -> ignore/optional heartbeat event
  |                            +-- data -> append data line
  |                            +-- event/id/retry -> store field
  |
blank line
  |
  v
emit one complete SSE event
  |
  v
clear event fields, keep decoder alive
#+end_src

A blank event with no data/event fields is ignored. Multi-line data joins with newline according to SSE semantics.

** Fragmentation invariant

For any valid byte sequence =B= and any partition of =B= into chunks, feeding those chunks in order must produce the same event sequence as feeding =B= in one chunk.

That becomes a property/fuzz test, not merely a few hand-picked chunk tests.

* Tool-call delta assembly

Streaming tool calls may arrive in fragments. The adapter maintains a per-call assembly record keyed first by provider call index and then stabilized by provider call id once known.

#+begin_src lisp
(defclass tool-call-assembly ()
  ((index :initarg :index :reader assembly-index)
   (id :initarg :id :initform nil :accessor assembly-id)
   (name :initarg :name :initform nil :accessor assembly-name)
   (argument-fragments :initform '() :accessor assembly-argument-fragments)
   (complete-p :initform nil :accessor assembly-complete-p)))
#+end_src

Example provider fragments:

#+begin_src json
{"delta":{"tool_calls":[{"index":0,"id":"call_1","function":{"name":"weather","arguments":"{\"ci"}}]}}
{"delta":{"tool_calls":[{"index":0,"function":{"arguments":"ty\":\"Columbus\"}"}}]}}
#+end_src

Canonical event sequence:

#+begin_src text
:tool-call-start        id=call_1 name=weather
:tool-call-arguments-delta "{\"ci"
:tool-call-arguments-delta "ty\":\"Columbus\"}"
:tool-call-ready        id=call_1 arguments={"city":"Columbus"}
#+end_src

The JSON parser runs only when the call is declared/known complete by the response lifecycle. If final assembled JSON is invalid, signal a typed incomplete/malformed tool-call condition with bounded raw diagnostic text.

Multiple parallel tool calls must remain correlated independently even when fragments interleave.

* Stream event model

Normalize provider stream data into typed events such as:

- =:message-start=;
- =:content-delta= with content subtype =:text=;
- =:reasoning-delta=;
- =:tool-call-start=;
- =:tool-call-arguments-delta=;
- =:tool-call-ready=;
- =:structured-output-delta=;
- =:usage=;
- =:provider-metadata=;
- =:message-complete=;
- terminal =:complete= / =:error= / =:cancelled=.

These should align with the Design 001 event model rather than define a parallel hierarchy.

Every event carries enough correlation metadata for concurrent invocations:

#+begin_src lisp
(make-instance 'stream-event
 :kind :content-delta
 :payload "hel"
 :metadata '((:request-id . "req-1")
             (:message-id . "msg-1")
             (:sequence . 7)
             (:content-kind . :text)))
#+end_src

Provider-native chunk payloads may be attached only under bounded debug/provider extensions; callers should not need them for ordinary use.

* Sync transport: Dexador

Dexador adapter responsibilities:

- canonical request -> Dexador options;
- TLS defaults remain verified;
- response status/headers/body normalization;
- streaming body path capable of feeding SSE incrementally rather than reading the entire response when available;
- deadline/timeout translation as far as Dexador permits;
- typed condition normalization;
- deterministic closure.

* Terminal arbiter and cancellation

One object owns the provider request terminal transition. Transport callbacks, SSE completion, cancellation and deadline all attempt to transition it atomically.

#+begin_src text
                        provider complete
                    +----------------------> COMPLETED
                    |
OPEN ---------------+ transport/provider --> FAILED
                    |
                    + cancellation --------> CANCELLED
                    |
                    + deadline ------------> FAILED(timeout)
#+end_src

Exactly one transition wins. All losers perform only idempotent cleanup/diagnostics.

Cancellation token callback invokes Carrier request cancellation for async requests. Once cancellation wins:

- no more public deltas are emitted;
- the stream terminates with typed cancelled state;
- late transport callbacks are discarded safely;
- the provider result cannot later become successful;
- any queued retry/backoff is cancelled.

OpenRouter may continue upstream work depending on downstream provider behavior, but local network processing must terminate immediately and accurately report local cancellation.

Representative guard:

#+begin_src lisp
(when (terminal-transition request-state :cancelled reason)
  (cancel-transport-handle handle)
  (channel-terminal-cancel event-channel reason))
#+end_src

=TERMINAL-TRANSITION= returns true only for the winning caller.

* Retry policy and classification

Automatic retry is allowed only when policy and failure stage make it safe.

| Failure point | Default replay decision |
|---------------+-------------------------|
| DNS/connect before request bytes | retryable |
| TLS handshake before request bytes | retryable only for transient failures, never certificate validation failure |
| 429 before semantic response | policy-controlled; honor Retry-After |
| selected 5xx before semantic response | policy-controlled |
| write failure after partial unknown request transmission | ambiguous; no default transparent retry |
| any stream delta already exposed | no transparent retry |
| embedding request before response | retryable under bounded policy |
| structured output validation after successful response | no transport retry by default |

Representative classifier:

#+begin_src lisp
(defun classify-openrouter-retry (failure request-state policy)
  (cond
    ((cancelled-p request-state) :never)
    ((deadline-expired-p request-state) :never)
    ((semantic-output-emitted-p request-state) :never)
    ((certificate-verification-failure-p failure) :never)
    ((rate-limit-error-p failure) :after-delay)
    ((safe-prewrite-transport-failure-p failure) :retry)
    (t :never)))
#+end_src

Honor =Retry-After= where valid. Apply bounded exponential backoff + jitter while clamping every sleep to the absolute request deadline.

Retry attempts emit metadata/events such as attempt number and sanitized reason. Secrets and raw Authorization headers never appear.

* Retry identity

One logical model invocation has one llm-agent request id even if multiple HTTP attempts occur. Each transport attempt gets its own attempt id.

#+begin_src text
logical request req-42
   |
   +-- attempt 1 -> connect error
   +-- attempt 2 -> HTTP 429
   +-- attempt 3 -> success
#+end_src

This prevents retries from looking like multiple model invocations in traces/checkpoints while still preserving attempt diagnostics.

* Errors

Normalize:

- HTTP status failures;
- OpenRouter JSON error envelopes;
- model/provider unsupported fields;
- malformed JSON;
- SSE parse limits;
- mid-stream error payloads after HTTP 200;
- incomplete tool argument JSON;
- final structured-output validation failures;
- usage/model metadata inconsistencies.

A partial-stream error includes already-observed usage/content metadata so applications can make informed decisions.

Representative condition:

#+begin_src lisp
(define-condition openrouter-provider-error (llm:provider-error)
  ((status :initarg :status :initform nil :reader openrouter-error-status)
   (provider-code :initarg :provider-code :initform nil
                  :reader openrouter-error-code)
   (request-id :initarg :request-id :initform nil
               :reader openrouter-error-request-id)))
#+end_src

Raw response bodies are bounded/redacted before being attached to diagnostics.

* Capability cache

Cache Models API records per base URL/credentials visibility context with fetched-at timestamp and configurable TTL. Expose force-refresh and no-cache modes. Capability decisions record whether they came from cache, live model profile or caller override.

Representative cache key:

#+begin_src lisp
(list :base-uri normalized-base-uri
      :model-id model-id
      :visibility-scope credential-scope-id)
#+end_src

Never use the secret credential itself as a cache key or printable value.

Capability cache lookup returns both profile and freshness state:

#+begin_src lisp
(multiple-value-bind (profile freshness)
    (lookup-model-profile cache model-id)
  ;; freshness = :fresh, :stale, :miss
  ...)
#+end_src

* Live and deterministic tests

Deterministic fixtures cover request JSON, ordinary responses, every-byte SSE fragmentation, keepalives, tool deltas, structured output, mid-stream errors, usage and retry classification.

Transport conformance runs the same local fixture server behavior through Dexador and hardened Carrier where semantics overlap.

** Cancellation race test

#+begin_src lisp
(test cancellation-wins-terminal-race
  (let ((run (make-controllable-stream-run)))
    (emit-provider-delta run "hello")
    (cancel-run run :user)
    (emit-provider-complete run)
    (is (eq :cancelled (run-terminal-state run)))
    (is (= 1 (run-terminal-transition-count run)))))
#+end_src

- non-stream chat;
- stream chat;
- a tool call;
- structured output with a compatible model;
- embeddings single/batch;

4. stream assembler, text/usage/tool-call deltas and terminal arbiter;

* Open design questions for maintainer approval

1. Exact names of canonical stream event kinds; this design recommends reusing Design 001 =:content-delta= plus subtype metadata instead of provider-specific =:text-delta= classes.
2. Default capability policy when model metadata is missing/stale: this design recommends =:attempt= for ordinary chat and =:require-known= only when caller explicitly requests strict preflight.
3. Default retry count/backoff envelope; should be conservative and deadline-bounded.
4. Whether raw provider chunks can be enabled in debug events; if yes, they must be opt-in, bounded and redacted.
5. Whether sync streaming through Dexador is required in the first provider PR or may land immediately after non-stream sync while SSE/Carrier work continues.

* Footnotes and Glossary

- *Capability cache*: time-bounded local model metadata used to reject/route incompatible requests before dispatch.
- *Terminal-state race*: competition between completion, failure, cancellation and timeout callbacks; exactly one may win.
- *Semantic output emitted*: any canonical stream event whose replay could be observed by application logic, excluding internal diagnostics.
- *Attempt id*: identity of one HTTP try within one logical model invocation.
