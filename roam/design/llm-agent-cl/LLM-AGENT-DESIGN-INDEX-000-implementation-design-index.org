* Cross-design invariants confirmed by review

The revised designs agree on these shared contracts:

1. **Project-owned semantics** — third-party futures, sockets, JSON objects, provider payloads and persistence implementations stay behind adapters.
2. **Exactly-once terminal state** — futures, provider streams, MCP requests and Carrier requests have one completion/failure/cancellation winner.
3. **Explicit cancellation/deadline** — child operations inherit/narrow runtime cancellation and monotonic deadlines.
4. **Bounded concurrency/backpressure** — worker queues, event channels, graph fan-out, MCP outstanding requests, retrieval batches and Carrier pools/waiters have limits.
5. **Deterministic graph mechanics** — task ids, reducer order, checkpoint lineage and pending-write recovery do not depend on thread/hash order.
6. **Secret redaction** — secrets remain configuration values and never enter logs/checkpoints/provider metadata by accident.
7. **Explicit resource ownership** — injected resources remain caller-owned unless ownership is transferred; internally created resources close deterministically.
8. **Fail-closed capability/security behavior** — required provider features, TLS identity verification, MCP versions and filter semantics are not silently downgraded.

* Dependency-aware implementation sequence

If the maintainer approves the design set, implementation should proceed in dependency order rather than attempting one giant feature branch:

1. **Core contracts** — packages, canonical values, config, conditions, cancellation/future/event primitives and test harness.
2. **Carrier hardening** — in =lost-rob0t/carrier=, independently tested/tagged before production async provider use.
3. **OpenRouter + transports** — Dexador sync, Carrier async, SSE, chat/models/embeddings/structured output.
4. **Graph + agent runtime** — state/reducers/supersteps/checkpoints/interrupts/tools/high-level agent.
5. **Retrieval/data plane** — documents/loaders/splitters/embeddings/stores/vector stores/retrievers and minimal RAG.
6. **MCP** — current client bindings first, then server export and compatibility fixtures.
7. **Parity closure** — run the full first-major-milestone matrix and close missing behavioral gaps before claiming feature parity.

Carrier hardening can proceed in its separate repository in parallel with early core work once Designs 001 and 006 expose stable integration expectations; llm-agent-cl must not consume Carrier as production async transport until its required TLS/lifecycle release gates pass.

Parallel work is acceptable only where dependency contracts are already stable. Each slice should get its own tests and PR rather than accumulating an unreviewable monolith.

* First-major-milestone definition

The first major milestone includes all capability classes required by [[id:llm-agent-research-001][parity research]], including retrieval. It is not complete merely when OpenRouter chat and a tool loop work.

Minimum closure classes include:

- provider-neutral canonical messages/content/results;
- sync + real async/cancellable transport semantics;
- OpenRouter chat, streaming, tools, structured output, model discovery and embeddings;
- graph reducers/supersteps/Send/Command/checkpoints/pending writes/interrupts/subgraphs/time travel;
- high-level agent built on the graph runtime;
- documents/loaders/splitters/embeddings/stores/vector stores/retrievers/RAG composition;
- current MCP client transports plus server export and explicitly selected compatibility fixtures;
- deterministic conformance tests and bounded live-provider smoke tests.
